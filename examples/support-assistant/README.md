# Ассистент поддержки TaskDesk

TaskDesk — вымышленный продукт; все пользователи и тикеты синтетические.
Реализация находится внутри DeepSeek Client, отдельный сервер с веб-интерфейсом.

## Запуск

Из корня репозитория:

    .\Start-Support-Assistant.cmd -BudgetUsd 0.20

Или PowerShell:

    .\Start-Support-Assistant.ps1 -BudgetUsd 0.20 -UserID U-100

Откроется http://127.0.0.1:8766. Launcher берёт DeepSeek-ключ из окружения
DEEPSEEK_API_KEY или существующей локальной конфигурации клиента, передаёт его
только серверному процессу. В браузер передаётся отдельный временный ключ
доступа к локальному сервису. В URL он находится во fragment и сразу удаляется
интерфейсом; для вкладки хранится в sessionStorage.

Ключ модели не хранится в коде, FAQ, CRM, веб-интерфейсе или журнале сервиса.
При ручном запуске локальный access token лежит в .support-assistant/state/access-token.txt.
Это ключ к localhost-сервису, не ключ DeepSeek.

Остановка:

    .\Start-Support-Assistant.ps1 -Stop

Для второго пользователя сначала остановите сервис, затем запустите с
-UserID U-200. Общий ledger .support-assistant/state/budget.json сохраняется
при перезапусках и смене выбранного пользователя. Смена пользователя — действие
локального оператора, а не параметр HTTP-запроса или выбор модели.

Если предыдущий процесс аварийно завершён, убедитесь, что он остановлен, прежде
чем вручную убирать оставшийся budget.json.lock. Не обнуляйте ledger для повтора.

## Что реализовано

- FAQ и описание продукта: [docs](docs).
- Пользователи и тикеты: [crm.json](crm.json).
- Настоящий MCP-сервер в отдельном stdio-процессе:
  support_get_user, support_list_tickets, support_get_ticket.
- MCP-процесс закреплён за одним пользователем; чужой тикет возвращает общий отказ.
  Нет инструментов записи, сброса пароля, подтверждения почты или платежей.
- FAQ разбивается по заголовкам. Разреженные TF-IDF векторы и cosine similarity
  выбирают до 4 фрагментов с score >= 0.10. Это локальный векторный RAG,
  без нейронных embeddings, Ollama и отдельной базы векторов.
- Поиск использует вопрос, категорию и error_code выбранного тикета.
  Документация и JSON загружаются при старте; для обновления перезапустите сервис.
- Agent получает FAQ и отдельно MCP context_results. Ответ проходит существующий
  agent.ValidateGroundedAnswer: цитаты совпадают с источниками, claim ссылается
  на quote, метаданные источников определяются приложением.
- Персональный answered должен цитировать FAQ и MCP-контекст. Смысл утверждений
  дополнительно требует проверки человеком; структурная проверка не доказывает
  причинно-следственную связь.
- Без релевантного FAQ возвращается локальный unknown без платного запроса.
- Один запрос DeepSeek на ответ; thinking disabled, JSON, максимум 1200 выходных
  токенов, без tools и автоматического восстановления невалидного ответа.
- В HTTP одновременно выполняется только один запрос ответа; второй получает 429.

## Контекст меняет ответ

| Пользователь / тикет | Один и тот же вопрос | Ожидаемый ответ |
|---|---|---|
| U-100 / T-100 | Почему не работает авторизация? | Почта не подтверждена; открыть письмо и подтвердить адрес |
| U-200 / T-200 | Почему не работает авторизация? | ACCOUNT_LOCKED; подождать 15 минут после последней неудачной попытки |
| U-100 / T-101 | Почему не работает экспорт PDF? | Тариф Free; PDF доступен на Pro, альтернатива CSV |
| U-100 / T-200 | Почему не работает авторизация? | Отказ в доступе к чужому тикету, запрос модели не отправляется |
| U-100 / без тикета | Погода на Юпитере завтра | unknown: в FAQ нет подтверждений; без запроса модели |

## API и границы

GET /health — состояние без данных пользователей.
GET /api/tickets — обращения выбранного пользователя.
POST /api/ask — JSON с question и ticket_id; общий вопрос допускает ticket_id="".
POST /api/shutdown — остановка локального сервиса оператором.

Все /api требуют Authorization: Bearer с локальным access token.
HTTP слушает только 127.0.0.1, проверяет Host и Origin, не разрешает CORS.
Web UI использует CSP с nonce и textContent для данных и ответов.
MCP child получает минимальное окружение без ключа DeepSeek.

Это локальный прототип для одного выбранного пользователя. Настоящие аккаунты,
SSO, многопользовательские сессии и удалённое размещение не реализованы.
Для production нужна серверная аутентификация с проверенной идентичностью,
защита персональных данных, HTTPS и политика доступа CRM. Не используйте
публичный туннель к этому демо или реальные данные без такой доработки.
