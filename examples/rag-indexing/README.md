# Домашка 21: локальная индексация и две стратегии chunking

Проверенная [запись OBS — ai_challenge_hw21.mp4](C:/Users/erdni/Videos/ai_challenge_hw21.mp4): 2 минуты 4 секунды, без озвучки. В настоящем TUI заново создан индекс через F2, затем временный слой статуса показал данные его файлов: чанки, метаданные, часть вектора, JSON-экспорт, повторное открытие и сравнение стратегий на десяти вопросах. Ввод автоматизирован. Платных API-вызовов нет. Видеопоток полностью декодирован без ошибок; проверены кадры создания базы, метаданных и итоговой таблицы.

Задание выполнено на трёх полных открытых документах RFC Editor:

| Документ | Оригинальные страницы | Слов в индексируемой копии |
|---|---:|---:|
| [RFC 2324: HTCPCP](https://www.rfc-editor.org/rfc/rfc2324.txt) | 10 | 2549 |
| [RFC 6585: Additional HTTP Status Codes](https://www.rfc-editor.org/rfc/rfc6585.txt) | 10 | 2001 |
| [RFC 7168: HTCPCP-TEA](https://www.rfc-editor.org/rfc/rfc7168.txt) | 7 | 1750 |
| **Суммарно** | **27** | **6300** |

RFC 2324 и RFC 7168 — информационные первоапрельские протоколы; RFC 6585 — технический документ HTTP. Объём установлен по последовательным номерам страниц в оригиналах, а не по искусственному форматированию. Корпус взят из TXT, поэтому поле `pdf_pages` индекса равно нулю. Исходники и уведомления об авторских правах сохранены в `sources/`. Индексируемые Markdown-копии находятся в `corpus/`: удалены повторяющиеся колонтитулы и оглавления, разделы оформлены заголовками. Содержимое разделов сохранено. URL, SHA256 и параметры обработки — в [sources.json](sources.json).

## Реализованный пайплайн

Документ → текст с заголовками → токенизатор → чанки → реальные локальные embeddings Ollama → индекс Qdrant Local → JSON-экспорт с векторами → проверка повторного чтения → сравнение поиска.

Используется существующий код [pipeline.py](../../projects/deepseek-client/rag-service/rag/pipeline.py), [chunking.py](../../projects/deepseek-client/rag-service/rag/chunking.py), [documents.py](../../projects/deepseek-client/rag-service/rag/documents.py) и [models.py](../../projects/deepseek-client/rag-service/rag/models.py). Обёртка [build.py](build.py) подготавливает корпус, вызывает этот пайплайн, экспортирует индекс и проверяет результат. Платные LLM API не используются.

Каждый чанк содержит `source`, `title`, `file`, `section`, `chunk_id`, `text`, `strategy`, `start_char`, `end_char`, `tokens` и `page`. Для TXT/Markdown `page` равен null; номера исходных страниц зафиксированы отдельно в sources.json. В переносимых индексах к чанку добавлен `embedding`.

Модель эмбеддингов — `nomic-embed-text:latest`, размерность 768. Digest конкретной модели зафиксирован в индексе. Для обеих стратегий используется одна модель и только текст чанка; метаданные не добавляются к тексту для эмбеддинга. Это делает сравнение стратегий более прямым.

## Сравнение

Обе стратегии ограничены 400 токенами, overlap 60. Fixed нарезает документ окнами без учёта разделов. Structured сначала выделяет разделы по Markdown-заголовкам, затем режет длинные разделы окнами; между самостоятельными разделами overlap не добавляется.

| Показатель | Fixed | Structured |
|---|---:|---:|
| Чанков | 30 | 72 |
| Токенов: минимум / среднее / максимум | 200 / 387.3 / 400 | 5 / 143.0 / 400 |
| Чанков, пересекающих несколько разделов | 28 | 0 |
| Размер JSON-индекса, байт | 595510 | 1324275 |
| Hit@5 без reranking | 1.00 | 1.00 |
| MRR@5 без reranking | 0.80 | 0.95 |
| Hit@5 с reranking | 1.00 | 1.00 |
| MRR@5 с reranking | 0.85 | 0.90 |

Контрольные вопросы и дословные эталонные фрагменты заданы заранее в [questions.json](questions.json). Для попадания требуется правильный файл и полный текст эталонной цитаты внутри найденного чанка. Кандидатов до 20, результатов до 5. Hit@5 — найден ли хотя бы один эталон; MRR@5 — обратный ранг первого найденного эталона. Полные результаты и время: [retrieval-comparison.md](retrieval-comparison.md); параметры и проверки: [results.json](results.json).

На этом наборе structured лучше сохраняет разделы и без reranking чаще ставит нужный текст первым, но создаёт больше векторов и занимает больше места. Reranking улучшил MRR у fixed, но немного ухудшил у structured. Поэтому его нельзя объявить безусловным улучшением. Это небольшой заранее составленный тест, а не доказательство качества на любых документах; замеры времени одиночного запуска не являются полноценным benchmark.

## Повторный запуск

Нужны готовое Python-окружение RAG, кэш токенизатора/reranker и работающий Ollama с установленным `nomic-embed-text:latest`. Скрипт использует localhost, Qdrant Local и модели из кэша. Пример из корня этого проекта:

```powershell
& 'C:/Users/erdni/Documents/ChatGPT/RAG/.venv/Scripts/python.exe' `
  examples/rag-indexing/build.py `
  --model-cache 'C:/Users/erdni/Documents/ChatGPT/RAG/data/models' `
  --output artifacts/hw21-second-run
```

Указывайте новую папку вывода: скрипт отказывается перезаписывать существующий index.json. `--prepare-only` выполняет только преобразование источников и подсчёт объёма. Готовую папку `examples/rag-indexing/corpus` можно также добавить в обычный клиент через F2 → создание базы. Предыдущее сравнение ответов для домашки 22 не переснималось и не заменялось этим поисковым тестом.
