# День 29: оптимизация локальной LLM для RAG

Кейс — короткие ответы по RFC с точными цитатами. Используется тот же индекс
`artifacts/hw21/index.json`, локальные Qdrant, nomic embeddings и CPU reranker.
Облачных запросов нет. Все ответы benchmark получены через обычный TUI и настоящий Ollama.

## Варианты

| Вариант | Модель / квантование | Temperature | Max output | Реальный контекст | RAG-шаблон |
|---|---|---:|---:|---:|---|
| before | Qwen3.5 4B / Q4_K_M | 0 | 2048 | 16384 | прежний |
| q4 | Qwen3.5 4B / Q4_K_M | 0.1 | 1024 | 8192 | compact |
| q8 | Qwen3.5 4B / Q8_0 | 0.1 | 1024 | 8192 | compact |

`compact` добавляет порядок «найти короткую точную цитату → сформулировать
минимальный ответ», ограничивает лишние факты и даёт пример на синтетических
данных о хранении логов. В шаблоне нет ответов на проверочные RFC-вопросы.
У обоих оптимизированных Modelfile задан seed 29; базовый профиль seed не задаёт.
Схема JSON, проверка точности цитат и отказ при отсутствии подтверждений остаются
общими для всех вариантов. Семантическую поддержку утверждений оцениваем отдельно.

Параметр профиля `rag_template: "compact"` действует только для ответов по базе
знаний. Пустое значение сохраняет прежнее поведение. Неизвестное значение отвергается
при загрузке конфигурации. Temperature задана в `generation` всего файла конфигурации;
обычная смена `/profile` сама по себе её не меняет.

## Воспроизведение

Из корня репозитория, после подготовки Ollama и локального RAG-окружения:

```powershell
ollama pull qwen3.5:4b-q8_0
ollama create qwen3.5:4b-rag-opt-q4 -f examples/local-optimization/Modelfile.q4
ollama create qwen3.5:4b-rag-opt-q8 -f examples/local-optimization/Modelfile.q8
cd projects/deepseek-client
go test -c -o ../../bin/hw29-demo.exe
cd ../..
./examples/local-optimization/benchmark.ps1 -Variant before -OutputDirectory "$PWD/examples/local-optimization/new-before"
./examples/local-optimization/benchmark.ps1 -Variant q4 -OutputDirectory "$PWD/examples/local-optimization/new-q4"
./examples/local-optimization/benchmark.ps1 -Variant q8 -OutputDirectory "$PWD/examples/local-optimization/new-q8"
```

Запускать последовательно: один индекс не должен одновременно открываться двумя
процессами Qdrant Local. Скрипт требует новую директорию и не перезаписывает результаты.
Пути Python и model cache в benchmark соответствуют существующему окружению этого ПК.
Подготовка и загрузка весов требуют сети; готовый pipeline выполняется локально.

## Протокол

Для каждого варианта — два повтора всех десяти вопросов
[дня 24](../rag-grounding/questions.json), отдельные свежие диалоги, без памяти,
истории и внешних инструментов. Поиск идёт через настоящий managed worker.
Предварительный поиск сохраняет доказательства для случая нулевых вызовов; для
остальных строк он заменяется контекстом фактического запроса. Полное время хода
включает поиск TUI и генерацию, но не предварительный поиск и не запуск worker.

Сохраняются сырые ответы, видимый результат, фактические параметры/сообщения HTTP,
Ollama runtime, модель и ресурсы. Runtime context проверяется после каждого вызова.
PASS интеграционного теста означает завершение сбора, а не правильность всех ответов.
Ошибки не повторяются до успеха и остаются в отчёте.

Медиана API включает реальную генерацию и HTTP, исключает retrieval и первоначальный
прогрев. Основная метрика памяти — `size_vram` выбранной модели из `/api/ps`
(выделенная Ollama VRAM, не точный пиковый расход отдельного запроса).
Опрос `nvidia-smi` примерно раз в секунду сохраняет общую занятую VRAM, загрузку и
мощность GPU. Working set — сумма процессов с именем `*ollama*` и отдельно `python*` на этом ПК.
Фильтр Ollama не включает runners `llama-server`, поэтому это НЕ полная RAM модели.
Полный расход RAM локальной LLM в этом benchmark не измерен; вывод о памяти модели
основан на её выделенной VRAM. Пустой набор процессов даёт null в сырых отсчётах.
Эти общесистемные значения включают фоновые процессы/другие резидентные модели и
не доказывают изолированное потребление тестируемой модели. Пики между отсчётами
могут быть пропущены. Замер мощности не является измерением энергии.

Это небольшая оптимизация на известном наборе, а не независимый тест обобщения.
Одновременно меняются шаблон, контекст и лимит; причинный вклад каждого изменения
не выделен. Сравнение q4/q8 сохраняет параметры и шаблон, но не является сравнением
с неквантованным BF16. Два повтора не доказывают стабильность на любых вопросах.

## Результат и запуск

Выбран Q8 для RAG: полностью подтверждены **18/20** ответов против **11/20** до
оптимизации, медиана API **7.311 s** против **9.444 s**. Два ответа Q08 всё ещё
отклоняются за неточную цитату. Это улучшение на проверенном наборе, не гарантия
отсутствия ошибок. Прежний результат дня 28 (12/20) остаётся историческим; здесь
сделан новый baseline с измерением ресурсов в текущих условиях.

Быстрый вариант Q4: **16/20**, медиана **3.88 s**. Его можно выбрать для экономии
VRAM и задержки, принимая больше ошибок. Выделенная VRAM выбранной модели:
до **3461.02 MiB**, Q4 **3189.02 MiB**, Q8 **4937.87 MiB**.
Более высокое квантование улучшило качество по сравнению с Q4, но увеличило память
и задержку. Размеры на диске, GPU и ограниченные RAM-метрики — в сравнении.

- [Полный отчёт](comparison.md), [машиночитаемые метрики](comparison.json)
- [До](before-20261010/review.json), [compact Q4](q4-20261010/review.json), [compact Q8](q8-20261010/review.json)
- [Профиль Q8](q8.json), [профиль Q4](q4.json)
- [Запуск](../../Start-Optimized-RAG.cmd), `Start-Optimized-RAG.ps1 -Variant q4` для быстрого варианта

Launcher создаёт отдельное состояние для выбранного варианта, использует обычный
клиент, сохраняет существующий пользовательский config и историю. В клиенте:
F2 → 7 → абсолютный путь `artifacts/hw21/index.json`. Оставьте tools включёнными.
В публичный config.example.json добавлены `ollama_rag_optimized` и `ollama_rag_fast`.
Для них задайте `/temp 0.1`, если переключаете профиль внутри другой конфигурации.

Офлайн-пересчёт: `python examples/local-optimization/report.py`; внешних запросов
и загрузок нет. Модельные ответы, цитаты, runtime context и фактические параметры
запросов проверяются до создания отчёта. Ручная смысловая оценка привязана к SHA256.
