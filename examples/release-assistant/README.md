# Домашка 35 — AI-помощник подготовки релиза

## Реальная задача

Перед выпуском DeepSeek Client нужно собрать изменения после предыдущей версии,
проверить проект и объяснить пользователю новые возможности и ограничения.
Ручная подготовка требует переключаться между Git, документацией, тестами и
описанием релиза. Это приложение собирает материалы и готовит комплект для ревью.

Реальный пример: диапазон `w6-hw5 → w7-hw4` этого репозитория — четыре коммита
и 113 изменённых файлов. Это настоящий Git-проект с исполненными проверками,
а не учебный набор фиктивных релизных данных.

## Как участвует AI

Приложение читает Git-объекты выбранных коммитов, сохраняет полный diff,
строит корпус из изменённых исходников и Markdown DeepSeek Client и подбирает
фрагменты через TF-IDF/cosine RAG с отдельным поиском по изменениям каждого коммита.
DeepSeek получает метаданные изменений, выбранные фрагменты и результаты проверок.
Он пишет изменения для пользователей, документированные шаги запуска/обновления
и риски. Каждое утверждение связано с точными цитатами и Git-источником.

Проверки выполняет приложение, а не модель. Оно экспортирует выбранный head
в отдельную папку и запускает фиксированные Go/Node/Python-команды. Модель
не получает инструменты shell, Git, записи или публикации и не решает,
успешны ли тесты. Статус готовности формируется программно.

## Запуск

Из корня репозитория, без ключа и без обращения к AI:

```powershell
.\Start-Release-Assistant.ps1 -DryRun
```

Этот режим сохраняет diff, контекст и результаты тестов. Если проверка не прошла
или runtime недоступен, процесс завершается с кодом ошибки. Даже при успешных
проверках AI-черновик отсутствует, поэтому readiness остаётся `blocked`.

Полная автоматизированная проверка через настоящие TUI submit/update:

```powershell
.\Start-Release-Assistant.ps1 -BudgetUsd 0.20 -Verify
```

Интерактивный режим с существующим TUI DeepSeek Client:

```powershell
.\Start-Release-Assistant.ps1 -BudgetUsd 0.20
```

После проверок введите в TUI напечатанную цель:
«Подготовь черновик релиза week-7-preview по выбранному диапазону и результатам проверок.»
Сессия одноцелевая: принимает эту цель для заранее выбранного кандидата;
повторная отправка в той же сессии показывает уже полученный результат.
Выход — `/exit`. `-Verify` не открывает видимый терминал и не записывает видео.

Параметры для следующего релиза:

```powershell
.\Start-Release-Assistant.ps1 -BaseRef w6-hw5 -HeadRef w7-hw4 -ReleaseVersion week-7-preview -BudgetUsd 0.20 -Verify
```

`ReleaseVersion` — метка черновика, а не команда создания тега. После появления
новых коммитов можно выбрать другой `HeadRef`, например `HEAD`. Base должен быть
предком head. Ссылки разрешаются в конкретные SHA до чтения; незакоммиченные
файлы в кандидат не входят. Приложение не выполняет fetch автоматически.

Нужны Git, Go соответствующей версии, Node и Python. Launcher использует локальный
bundled runtime Codex, если он установлен; иначе — команды из PATH. Пути можно
переопределить через `-NodePath` и `-PythonPath`. Зависимости Go должны быть уже
установлены в cache: проверки выполняются с `GOPROXY=off`, `GOSUMDB=off`,
`GOTOOLCHAIN=local`, `GOWORK=off`, read-only go.mod и без VCS stamping.

Ключ берётся из `DEEPSEEK_API_KEY` либо подходящей локальной конфигурации DeepSeek
Client. Содержимое конфигурации и личная история не попадают в prompt или отчёты.
Дочерним процессам проверок передаётся ограниченное окружение без ключей провайдера
и переменных включения платных интеграционных тестов. Проверки запускают код
выбранного коммита: используйте свои проверенные refs.

## Комплект результата

Каждый запуск создаёт новую папку `.release-assistant/runs/<время>-<id>`:

- `release-notes.md` — черновик изменений, настройки и рисков с цитатами;
- `changelog-draft.md` — заготовка записи changelog;
- `readiness-report.md`, `readiness.json` — программный статус и границы проверки;
- `input.json` — конкретные SHA, коммиты, файлы, выбранные источники и проверки;
- `changes.diff`, `changed-files.md` — полный Git diff и список файлов;
- `checks.json`, `*.log` — фактические результаты проверок;
- `completion.json`, `draft.json`, `usage.json` — ответ модели, проверенный формат и расход;
- `manifest.json` — SHA-256 готовых файлов и метаданные кандидата;
- `check-workspace/` — отдельный снимок исходников для тестов.

Существующие папки не перезаписываются. При ошибках сохраняются данные и
зарезервированные расходы. Файлы проекта, основной CHANGELOG и Git refs не меняются.

`manual_review_required` означает: перечисленные проверки успешны, AI-структура
и цитаты валидны, но человек должен проверить формулировки и решение о выпуске.
Любая неуспешная проверка или отсутствие валидного AI-черновика даёт `blocked`.
Публикация релиза не реализована и автоматически не выполняется.

[Описание релиза](release-notes.md), [changelog](changelog-draft.md),
[готовность](readiness-report.md), [проверки](verification.json).
Исходные [метаданные](input.json), [diff](changes.diff),
[проверенный AI-ответ](draft.json) и [manifest](manifest.json) сохранены рядом.

Подтверждено:

- Четыре коммита и 113 файлов из `w6-hw5 → w7-hw4`.
- Корпус: 46 файлов, 541 фрагмент; модели переданы 12 выбранных фрагментов.
  Полный diff сохранён локально; это не заявление о полном AI-аудите diff.
- Go tests / vet / build, 14 Node-тестов и пять Python-тестов кандидата прошли.
- Сам помощник прошёл полные Go tests / vet / build; отдельные тесты проверяют
  чтение коммитов вместо dirty-файлов, запрет symlink в архиве, цитаты, категории,
  бюджет, блокировку ledger, сбои модели и исключение ключей из окружения проверок.
- Негативный интеграционный прогон с недоступным Node вернул exit 1 и `blocked`
  без AI-вызова. Модель не может переопределить этот результат.
- Два реальных запроса DeepSeek через scripted TUI. После первого уточнена
  инструкция о полноте цитат и различении устаревшей документации и кода fixture.
  Оба прогона сохранены локально; здесь опубликован второй комплект.
- У второго черновика вручную проверены восемь утверждений по цитируемым
  фрагментам head. Структурная валидация сама по себе не доказывает полноту
  каждой цитаты: например, уточнения про `/help` и неизменность кода находятся
  в полном цитируемом фрагменте, но выбранные короткие цитаты отражают их частично.
  Это дополнительная причина оставить обязательное ручное ревью.

Первый dry run выявил недостающие support-fixtures в экспортируемом снимке;
набор путей исправлен, успешные прогоны проверены после исправления.
Ни одно неуспешное выполнение не представлено как успешное.

## Бюджет и ограничения

Разрешённый бюджет домашки — $0.20. Всего два платных запроса; резерв $0.03088260,
оценка по peak $0.007265568. Это не точное списание провайдера. Тарифы Flash
проверены 2026-10-17: input/cache/output — $0.30/$0.006/$1.20 за миллион токенов.
[Официальные тарифы](https://api-docs.deepseek.com/quick_start/pricing/).

Перед запросом резервируются UTF-8 байты сериализованного запроса + 4096
входных токенов и максимум 3500 выходных. Ledger синхронизируется до сети,
блокируется между процессами и сохраняется после ошибок. До трёх попыток на
общий ledger, без скрытых повторов. Thinking отключён, инструменты модели отключены.
Новый запуск требует актуального разрешения и бюджета; старый ledger не даёт
разрешения на новые API-запросы и не должен удаляться для обхода лимита.

Границы: до 256 изменённых файлов, 50 non-merge коммитов, diff до 4 MiB,
корпус до 4 MiB, до 16 выбранных фрагментов, AI-envelope до 100000 байтов.
Ограничения превышены — выполнение останавливается, частичный diff не принимается.
Код тестов из выбранного head исполняется; команды модели не исполняются.
Не заявляются проверка всего монорепозитория, нагрузочный тест, все платформы,
полный AI-аудит или автоматическая семантическая доказанность формулировок.
