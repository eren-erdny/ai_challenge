# Домашка 34 — ассистент для работы с файлами

DeepSeek самостоятельно исследует учебный TaskDesk через существующие инструменты
DeepSeek Client, исправляет документацию и создаёт карту API. Подготовка копирует
только исходный проект; выбранные файлы, поиск и содержимое правок определяет модель.

## Два сценария

1. «Приведи документацию об экспорте в соответствие с текущим кодом TaskDesk».
   Агент находит код и документы, исправляет README и FAQ и перечитывает их.
2. «Найди все места использования API экспорта и создай карту зависимостей».
   Агент исследует реализацию, API, UI и тесты и создаёт `docs/export-api-map.md`.

Полные цели сохранены в [verification.json](verification.json).
Пользователь не задаёт список файлов для чтения или последовательность инструментов.
Имя создаваемого документа задаётся как требуемый результат второй цели.

## Запуск

Из корня репозитория, после получения актуального разрешения на платный прогон:

```powershell
.\Start-File-Assistant.ps1 -BudgetUsd 0.20
```

Откроется существующий TUI DeepSeek Client, подключённый к свежей рабочей копии.
Введите по очереди две напечатанные при запуске цели. Для выхода — `/exit`.
API-ключ берётся из `DEEPSEEK_API_KEY` или подходящей существующей конфигурации
DeepSeek; он не записывается в учебный проект или результаты.

Автоматизированная проверка обеих целей через настоящее TUI submit/update:

```powershell
.\Start-File-Assistant.ps1 -BudgetUsd 0.20 -Verify
```

Режим `-Verify` не открывает видимое окно TUI и не является видеозаписью.
Он использует тот же обработчик отправки вопроса и обновления ответа приложения.
Модель реальная, файловые операции реальные, сохранённые ответы не подставляются.

Требуются Go, ключ DeepSeek и доступ к официальному API. Для тестов учебного
JavaScript-проекта дополнительно нужен Node.js с поддержкой `node --test`.

Каждый запуск создаёт новую папку `.file-assistant/runs/<время>-<id>/`:

- `before/` — неизменённая исходная копия;
- `workspace/` — реальные файлы после работы агента;
- `tools.json` — имена инструментов, параметры, результаты и ошибки;
- `answers.json` — видимые ответы автоматизированного TUI-прогона;
- `changes.diff` — unified diff из фактических байтов файлов;
- `files.json` — список изменений, SHA-256 и расход;
- `verification.json` — результат проверки двух целей.

После ручного выхода проверка тоже выполняется. Если две цели не выполнены,
возвращается ошибка, а промежуточные файлы и расходы сохраняются.

Повторный запуск начинает с исходного fixture и не удаляет предыдущие результаты.
Все запуски разделяют `.file-assistant/budget.json`; перезапуск не обнуляет расходы.
Старый ledger не является разрешением на новый платный прогон. При исчерпании
лимита работа останавливается; не удаляйте ledger для обхода бюджета.

Полные Go tests / vet / build прошли; семь Node-тестов прошли до и после изменений.
`git apply --check --no-index` подтвердил применимость diff к исходной копии.
Отдельный локальный replay реального журнала на свежем fixture получил те же
байты файлов без новых API-запросов. Это проверка воспроизводимости операций,
а не второй самостоятельный прогон модели: формулировки при новых генерациях
могут отличаться.

Локально воспроизвести сохранённые операции без API:

```powershell
$env:FILE_ASSISTANT_REPLAY = (Resolve-Path './examples/file-assistant').Path
Push-Location './projects/deepseek-client'
go test ./fileassistant -run TestRecordedToolReplay -count=1 -v
Pop-Location
Remove-Item Env:FILE_ASSISTANT_REPLAY
```

Живой прогон: 12 запросов модели, резерв $0.09549330, оценка по peak $0.005373936
при разрешённом бюджете $0.20. Это не точное списание провайдера.
[Тарифы DeepSeek](https://api-docs.deepseek.com/quick_start/pricing/) проверены
2026-10-17: Flash, input/cache/output — $0.30/$0.006/$1.20 за миллион токенов.
Thinking отключён, максимум 2200 выходных токенов на запрос.
Перед каждым запросом резервируются сериализованные UTF-8 байты запроса + 4096
входных токенов и полный выходной лимит; ledger синхронизируется до сети.
Лимиты: $0.20, 24 запроса на общий ledger, envelope до 65000, без скрытых повторов.

## Границы

Используется доступный tooling, отдельный MCP для этой домашки не требуется.
Применяются существующий pre-execution tool guard и ограниченный файловый executor:
строгие параметры, относительные пути, запрет выхода из workspace и симлинков.
Дополнительная политика демо разрешает запись только в README, FAQ и карту API;
код и тесты доступны только для чтения. Модель не получает shell, Git или сеть
в качестве инструмента. Учебный код проверяет правила экспорта и возвращает
метаданные, полноценный PDF не генерирует.

Исходный fixture встроен в бинарник из
[fileassistant/fixture](../../projects/deepseek-client/fileassistant/fixture).
Реализация: [session.go](../../projects/deepseek-client/fileassistant/session.go),
[TUI/CLI](../../projects/deepseek-client/file_assistant_demo.go).
Рабочие конфигурация и переписки пользователя не меняются. Commit/push/merge
не выполнялись. Запись видео описана ниже.
