# День 30: приватная LLM на VPS

На Ubuntu работают Ollama с `smollm2:135m` и отдельный API `private-llm`.
Существующий DeepSeek Client остаётся на Windows. Нового интерфейса чата нет.
Платные облачные API не используются.

## Запуск чата на ПК

Из корня репозитория в PowerShell:

```powershell
& ./examples/private-llm/Start-Chat.ps1 -Server root@YOUR_SERVER
```

Нужны Go, OpenSSH и уже добавленный на VPS ключ
`$env:USERPROFILE\.ssh\hw1_deploy`. Скрипт собирает существующий клиент,
создаёт собственный SSH-туннель на локальном порту 11438 и запускает обычный TUI.
При выходе закрывается только этот туннель. Если ключ защищён passphrase,
сначала загрузите его в ssh-agent. Порт 11438 должен быть свободен.

История и настройки этого запуска изолированы в `.local-llm/private-service/`.
Личные настройки и переписки не копируются на сервер. Файловые инструменты
для слабой модели оставьте выключенными (`/tools off`). Модель предназначена
для простого чата и проверки интеграции; качество русского языка ограничено.

## API и приватность

- Ollama: `127.0.0.1:11434` на VPS.
- API с ограничениями: `127.0.0.1:11436` на VPS.
- HTTP `POST /api/chat` и OpenAI-совместимый `POST /v1/chat/completions`.
- `GET /health` показывает настройки процесса, не гарантирует здоровье модели.
- `GET /v1/models` возвращает разрешённую модель.
- Текстовые сообщения user/system/assistant; потоковый вывод и вызовы инструментов
  не поддерживаются этим минимальным сервисом.

Авторизация выполняется SSH-ключом. HTTP доступен через зашифрованный туннель;
публичный порт API не открывался. Обладатели shell-доступа к VPS считаются
доверенными: они могут обратиться напрямую к Ollama в обход прокси.

Для отдельных HTTP-проверок откройте туннель в отдельном PowerShell:

```powershell
ssh -N -o ExitOnForwardFailure=yes -i "$env:USERPROFILE\.ssh\hw1_deploy" -L 127.0.0.1:11437:127.0.0.1:11436 root@YOUR_SERVER
```

В другом окне:

```powershell
Invoke-RestMethod http://127.0.0.1:11437/health
& ./examples/private-llm/verify.ps1
```

Проверочный сценарий расходует пять разрешённых запросов. Перед повторным
запуском подождите минуту; активный чат использует тот же общий лимит.

## Принудительные ограничения

| Ограничение | Поведение |
|---|---|
| Rate limit | 5 принятых запросов за скользящие 60 секунд, общий для сервиса; далее HTTP 429 и Retry-After |
| Контекст | Всегда `num_ctx=512`; запрос большего значения через options отклоняется HTTP 400 |
| Ответ | До 128 токенов; меньший лимит разрешён, превышение и отрицательные значения отклоняются |
| Вход | До 4096 символов суммарного текста и 32 сообщений; тело HTTP до 32768 байт |
| Параллелизм | 1 генерация и до 2 ожидающих запросов; переполнение очереди HTTP 503 |
| Модель | Только `smollm2:135m` |

Прокси заново собирает запрос к Ollama из разрешённых полей. Произвольные
options клиента не пересылаются. Лимит символов не равен точному числу токенов:
вход вместе с шаблоном модели может превышать окно, и Ollama может усечь его.
Это сервис с ограниченным окном контекста, а не точный предварительный токенизатор.
Rate limit хранится в памяти и сбрасывается при перезапуске сервиса.

## Код и развёртывание

[Исходник API](../../projects/deepseek-client/cmd/private-llm/main.go),
[тесты защиты](../../projects/deepseek-client/cmd/private-llm/main_test.go),
[systemd unit](private-llm.service), [профиль клиента](client.example.json).

При уже установленной Ollama с моделью, из PowerShell:

```powershell
& ./examples/private-llm/Deploy.ps1 -Server root@YOUR_SERVER
```

Скрипт собирает и загружает только API, не клиент. Для установки systemd нужны
права root. Сервис запускается с DynamicUser, ProtectSystem, ProtectHome,
NoNewPrivileges и ограничением памяти 128M. Бинарник находится в `/opt/hw30/`.

Ollama настроена через `/etc/systemd/system/ollama.service.d/hw30-limits.conf`:
`OLLAMA_NUM_PARALLEL=1`, `OLLAMA_MAX_LOADED_MODELS=1`,
`OLLAMA_CONTEXT_LENGTH=512`. Swap 2 GiB уже активен; это запас, не замена RAM.

```bash
systemctl status ollama private-llm
journalctl -u private-llm -n 30 --no-pager
```
