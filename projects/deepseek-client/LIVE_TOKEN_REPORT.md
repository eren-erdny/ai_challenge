# Проверка токенов через реальный DeepSeek API

Дата: 10 сентября 2026, 19:02 UTC. Модель: `deepseek-flash`.
Выполнены ровно три запроса. Разрешённый бюджет: $1. Повторных попыток не было.
Настройки: temperature=0, thinking disabled, max_tokens=64; локальная проверка
контекста отключена, чтобы получить отказ именно от сервера.

## Методика

Один и тот же вопрос: "What is the project name and budget mentioned earlier?
Answer in one short sentence."

Начальная история содержала факт: проект North, бюджет 75000 рублей, и
подтверждение ассистента. Для длинного диалога добавлены предыдущий реальный
ответ и синтетический блок фоновых данных из 2000 повторений ` x`. Для
переполнения добавлен блок из 1100000 повторений. Это контролируемая нагрузка
на контекст, а не миллион токенов естественной переписки. Ответы и HTTP-ошибка
получены от настоящего API. Использована временная история вне пользовательских
диалогов; после теста она удалена. Ключ в отчёт не записывался.

## Стоимость

По опубликованным тарифам Flash на дату проверки: off-peak вход без кэша
$0.15/1M, выход $0.60/1M; peak вдвое дороже. Вызовы прошли в 19:02 UTC,
то есть вне опубликованных пиковых интервалов.

Суммарный расчёт за два успешных запроса: **$0.00033870**. Консервативная
оценка по peak-тарифу: **$0.00067740**, она сохранена построчно в JSON.
Это расчёт по usage, не проверка фактических списаний в личном кабинете.
Стоимость отказа API не сообщил. Даже резерв для всех трёх запросов,
рассчитанный до отправки по байтовому объёму и верхнему тарифу, составил $0.663083.

Источник тарифов и лимитов: [DeepSeek Models & Pricing](https://api-docs.deepseek.com/quick_start/pricing/).
Справочник цен в основном клиенте содержит старые значения; для этого отчёта
они не использовались. Тарифы и возможный роутинг моделей нужно обновлять отдельно.

## Что ломается

Третий запрос получил HTTP 400, `invalid_request_error`. Сервер сообщил:

```text
maximum context length: 1048576
messages: 1102137
completion reserve: 64
requested total: 1102201
```

Ответ не сгенерирован. Агент вернул ошибку, а все 10 сообщений истории остались
без изменений. Без нового диалога или уменьшения контекста повтор того же
запроса не решит проблему. Автоматического сокращения истории пока нет.

## Выводы

- При одинаковом новом вопросе вход вырос с 41 до 2089 токенов, примерно в 51 раз.
- Расчётная цена запроса выросла примерно в 20.5 раза: выход остался равен 16 токенам.
- Время в двух единичных измерениях почти не изменилось; этого недостаточно для
  вывода о зависимости скорости от контекста.
- Локальная эвристика существенно недооценивает повторяющийся текст: 1111 против
  2089, а при переполнении 551172 против 1102137. Она не гарантирует защиту от
  лимита. Для точной проверки до вызова нужен токенизатор соответствующей модели.
- Точные расходы успешных вызовов следует брать из API usage.

Сырые результаты: [live-token-results.json](live-token-results.json).
В этом историческом JSON поле `RequestEstimate` обозначало только последнее
сообщение пользователя. В актуальном коде оно переименовано в
`LastUserMessageEstimate`; полный текущий запрос — `InputActual` из `prompt_tokens`.
Повторяемый платный тест: `TestLiveTokenExperiment` в `live_tokens_test.go`.
Без `DEEPSEEK_LIVE_TOKEN_TEST=1` он пропускается и не вызывает API.
