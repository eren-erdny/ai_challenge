# Эксперимент режима task

Цель — проверить автоматические переходы, паузу и продолжение без повторного
описания задачи. Ручных команд `/task` нет: состояние меняется вместе с обычным
ответом модели и проверяется агентом.

## Основной сценарий

```text
/new
/mode task
Подготовь и проверь HTTP endpoint состояния.
Продолжай.
Поставь задачу на паузу: нужно согласовать контракт.
Что сейчас происходит с задачей?
Возобнови задачу.
Продолжай.
```

После первого запроса состояние должно начаться с `planning`. Каждый ответ
завершается строкой вида `[task:planning] шаг → ожидаемое действие`. Этап может
остаться прежним или перейти только на следующий:
`planning → execution → validation → done`.

На паузе состояние сохраняет этап и показывает `(пауза)`. Ответ, снимающий
паузу, ещё не может одновременно перейти на следующий этап. Следующее
«Продолжай» использует сохранённые цель и прогресс.

## Проверка восстановления

Закройте клиент после постановки задачи на паузу, снова запустите его и введите:

```text
/mode task
Продолжай.
```

Ожидание: состояние загружается из `memory/tasks/<ConversationID>.json`; цель
пересказывать не нужно. После этапа `done` можно обычным сообщением дать другую
задачу, и она должна начать отдельный цикл с `planning`.

Автоматические тесты проверяют сценарий «задача → Продолжай», сохранение между
экземплярами хранилища, паузу и возобновление на каждом этапе, запрет скачков,
изоляцию Conversation ID, защиту от устаревшей записи и строгий JSON-протокол.
Live API для этих проверок не нужен.
