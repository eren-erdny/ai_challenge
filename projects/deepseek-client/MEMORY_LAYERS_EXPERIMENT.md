# Эксперимент явных слоёв памяти

Цель — проверить, какие данные попадают в short-term, working и long-term и как
каждый слой меняет контекст ответа. Используйте один профиль, temperature `0`,
режим `free`, tools off и одинаковую стратегию контекста.

## Сценарий

Начните новый диалог и сохраните явные записи:

```text
/new
/mode free
/temperature 0
/tools off
/memory sliding
/memory set working task_goal Подготовить ТЗ сервиса Orion
/memory set working deadline Пятница 18:00
/memory set long-term preferred_language Русский
/memory set long-term user_role Архитектор
/memory show all
```

Отправьте сообщение, которое должно остаться только в краткосрочной памяти:

```text
Для текущего обсуждения кодовое слово «янтарь». Не сохраняй его в другие слои.
```

Добавьте достаточно нейтральных сообщений, чтобы кодовое слово вышло за
`keep_last`, затем спросите:

```text
Назови цель, дедлайн, предпочитаемый язык, мою роль и кодовое слово.
```

Ожидание при `sliding`: working и long-term сохранят первые четыре значения, а
кодовое слово исчезнет вместе со старой краткосрочной историей.

Создайте новый диалог:

```text
/new
/memory sliding
/memory show all
```

Ожидание: short-term и working пусты, long-term всё ещё содержит язык и роль.
После `/memory delete long-term user_role` роль должна исчезнуть из следующего
запроса, а остальные записи остаться.

## Что проверяют автоматические тесты

- short-term, working и long-term физически записываются раздельно;
- working одного Conversation ID не виден другому;
- long-term доступен из нового диалога;
- set, update и delete выполняются только для явно указанного слоя;
- запрос модели содержит long-term и working перед эффективной историей;
- синтетический ответ меняется с `deadline unknown` на `deadline Friday` после
  подключения working memory;
- explicit-слои совместимы со Sliding Window и учитываются в context preflight.

Реальный ответ зависит от выбранной модели. Live API-прогон не является частью
offline-тестов и требует отдельного разрешения и лимита.
