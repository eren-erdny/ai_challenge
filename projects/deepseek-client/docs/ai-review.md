# Автоматическое ревью PR через DeepSeek

Реализация: [workflow](../../../.github/workflows/ai-review.yml),
[CLI](../cmd/review-pr/main.go), [сборщик и RAG](../prreview),
[публикация](../../../scripts/ai-review/publish.py).
[Живой пример](../../../examples/ai-review/README.md).

## Как работает

1. GitHub Action реагирует на opened/synchronize/reopened/ready_for_review для
   недрафтового PR с изменениями в projects/deepseek-client.
2. Из точного base SHA собирается доверенный Go CLI. Head PR не checkout-ится:
   его diff читается из Git-объектов относительно merge-base.
3. Корпус README, docs и исходников берётся из base SHA. Разбиение: до 40 строк,
   шаг 30. TF-IDF векторы и cosine similarity выбирают до 3 фрагментов документации
   и 5 фрагментов кода, всего до 24000 байт. Это локальный векторный RAG,
   без нейронных embeddings, Ollama и отдельного сервера.
4. Один запрос deepseek-flash, JSON, thinking disabled, max_tokens=1600.
   Модель получает diff, список файлов, строки и найденный контекст.
5. Валидатор запрещает неизвестные/повторные JSON-поля, неверные категории,
   неподтверждённые строки diff и отсутствующие в контексте цитаты.
   Невалидное или оборванное ревью не публикуется; автоматических повторов нет.
6. Фиксированный Python publisher создаёт или обновляет один комментарий бота
   с разделами «Потенциальные баги», «Архитектурные проблемы», «Рекомендации».
   Перед записью повторно проверяет head/base и открытое состояние PR.
   Проверка и запись не атомарны: SHA видны в тексте на случай гонки.
7. JSON, Markdown, входной контекст и ledger сохраняются как Actions artifact.

## Первое включение GitHub

Сначала изменения reviewer, scripts и workflow должны попасть в базовую ветку.
Первый PR, добавляющий reviewer, нельзя проверить его же кодом из ещё не обновлённой
базы. Включайте автоматизацию после этого первоначального объединения.

В Settings → Secrets and variables → Actions:

- Repository secret DEEPSEEK_API_KEY — ключ DeepSeek.
- Repository variable AI_REVIEW_BUDGET_USD — например 0.02, максимум 0.20 на запуск.
- Repository variable AI_REVIEW_ENABLED=true — явно включает платные запуски.
  При отсутствии/false workflow пропускается. Для остановки выставьте false.

Необязательная variable AI_REVIEW_HEAD_BRANCH ограничивает запуск одной head-веткой;
для автоматизации всех собственных PR оставьте её пустой. Для ограниченной проверки
используется codex/ai-pr-review-demo.

Затем создайте PR внутри этого репозитория с небольшим изменением Go-кода.
В Actions должен завершиться DeepSeek PR review, в PR появиться комментарий.
Это первоначальный вариант для собственных PR: fork и Dependabot пропускаются.
Публикация требует разрешённого GITHUB_TOKEN pull-requests:write в политике
репозитория/организации. Никаких одобрений, merge или правок кода бот не делает.

AI_REVIEW_ENABLED включает расходы на каждый будущий подходящий запуск.
Бюджет CI ограничивает отдельный запуск; он не является общим лимитом аккаунта
или всех PR. Повторные запуски получают отдельный ledger. До явного включения
workflow не расходует средства. Локальный тестовый бюджет хранится отдельно.

## Защита и границы

Ключ передаётся только в окружении шага генерации; GitHub token — publisher.
Модель не получает инструменты, токены или право выбирать API/команды.
Данные PR считаются недоверенными. Код, тесты, зависимости и hooks PR не запускаются.
Доверенными считаются базовая ветка, её зависимости и workflow собственных
участников репозитория. Это не песочница для злоумышленника с правом менять workflow.

Используются только полные SHA и буквальные Git pathspec; чтение файлов идёт
через blob ID. Символические ссылки и submodules исключены из корпуса.
Hidden paths, config.json, conversations/memory/data/models/examples/vendor/node_modules
и неподдерживаемые расширения исключены. Это фильтр области, не secret scanner:
секрет, ошибочно закоммиченный в обычный исходник/README, попадёт в контекст.
Ключи и частные данные нельзя хранить в отслеживаемой документации/коде.

Ограничения: 40 изменённых файлов в области, 60000 байт на diff файла,
80000 байт общего diff, корпус до 400 файлов/8 MiB. Файлы корпуса больше
128 KiB и chunks больше 16000 байт не индексируются; результаты retrieval ограничены.
Выход за общие лимиты приводит к ошибке вместо частичного «успешного» ревью.
Пропущенные diff-файлы перечисляются. Вне области проекта файлы не анализируются.
Без доступного контекста/подходящего diff запрос не отправляется.

Цитаты и номера строк проверяются механически, смысл замечаний — человеком.
Отсутствие замечаний не означает корректность PR. Раздел может честно быть пустым.

## Локальный запуск

Из корня репозитория создайте одноразовый тестовый репозиторий:

    python scripts/ai-review/make_fixture.py .project-assistant/pr-review/my-fixture

В fixture.json находятся repo/base_sha/head_sha. В projects/deepseek-client:

    go run ./cmd/review-pr --repo PATH --base FULL_BASE_SHA --head FULL_HEAD_SHA --output FRESH_DIR --dry-run

Живая команда дополнительно требует DEEPSEEK_API_KEY и --budget-usd 0.20.
Для нескольких запусков укажите один --ledger PATH; резерв не освобождается
после ошибки, API-запросов без предварительного резерва нет.
Выходная папка всегда новая; lock защищает общий ledger от параллельных запусков.

Резерв: размер JSON-запроса в UTF-8 байтах плюс 4096 как верхняя оценка входных
токенов и 1600 выходных токенов, cache miss, peak. Тарифы Flash на 2026-10-16:
вход $0.30, cache hit $0.006, выход $1.20 за миллион токенов.
[Источник тарифов](https://api-docs.deepseek.com/quick_start/pricing/).
После изменения тарифов формулу необходимо обновить. Ledger usage — оценка
по известным токенам и peak, а не выписка списаний провайдера.

## Проверка

    go test ./...
    go vet ./...
    go build ./...
    python -m unittest discover -s scripts/ai-review -v

Опциональный TestPRReviewLive требует отдельного текущего разрешения, бюджета,
новой выходной папки и общего ledger; обычный go test его пропускает.
Живая проверка выполнена локально, реальный GitHub runner ещё не запускался.
