# Базы знаний в DeepSeek Client

## Как пользоваться

1. Нажмите **F2** или введите `/kb`.
2. Выберите **1 — Создать базу**.
3. Введите название, например «Работа».
4. Вставьте путь к папке документов или одному файлу.
5. Дождитесь подготовки. Новая база автоматически выбирается для этого чата.
6. Задавайте вопросы обычным сообщением. Клиент сам выполняет поиск и передаёт найденные фрагменты модели; перед ответом показывает источники.

На первом создании клиент подготовит Python-окружение и скачает модели.
Это может занять несколько минут и требует интернета. Нужен установленный
Ollama и Python 3.12+; Python также может быть найден в runtime Codex.
Для запуска из исходников нужен Go. Установленные Go и Ollama не скачиваются
клиентом. При отсутствии компонента меню сообщает, что установить.

Первичная подготовка и индексация выполняются в фоне интерфейса. Ctrl+C
закрывает клиент и отменяет работу. При ошибке новая база не публикуется,
а прежняя версия остаётся доступной. Исходные файлы остаются на своих местах.

## Другие базы и документы

В F2 / `/kb` доступны:

- **Создать базу** — отдельная база со своим именем и индексом.
- **Выбрать базу для чата** — переключение между сохранёнными базами.
- **Добавить файл или папку** — добавить источник в выбранную базу и обновить индекс.
- **Обновить индекс** — перечитать все источники после изменения документов.
- **Убрать источник** — исключить его из базы; оригинальные файлы не удаляются. В базе должен остаться хотя бы один источник.
- **Отключить базу** — обычный чат без автоматического поиска.

Выбор сохраняется отдельно для каждого диалога. Новый диалог начинается без
базы; при возвращении в прежний восстанавливается его выбор. Одна база может
использоваться несколькими чатами. `/tools off` также отключает поиск.

Поддерживаются TXT, Markdown, PDF с текстовым слоем и исходный код. PDF без
текста требует OCR. Скрытые файлы, окружения и служебные каталоги исключаются.
Добавляйте только явно выбранные источники. При нескольких источниках пути
в ответах имеют префиксы, позволяющие различать одноимённые файлы.

## Где хранится и как работает

Если окружение и модели уже подготовлены в другом RAG-проекте, их можно
подключить без повторной установки. Перед обычным запуском клиента задайте
абсолютные пути `DEEPSEEK_RAG_PYTHON` (его python.exe) и
`DEEPSEEK_RAG_MODEL_CACHE` (его каталог моделей). Клиент проверяет зависимости
и локальные модели, но не устанавливает пакеты в указанное окружение и не
скачивает модели в указанный кэш. Индексы баз из меню остаются отдельными.

Каталог `knowledge` рядом с пользовательским `config.json` содержит:

- `catalog.json` — базы, пути источников и выбор для чатов;
- `.venv` и `models` — общее окружение и кэш;
- `runtime` — Python-код, извлечённый из встроенного в Go-приложение пакета;
- `bases` — версии локальных индексов Qdrant и manifests.

Менеджер сам запускает постоянный Python-процесс по stdio для выбранной базы
и при необходимости локальный Ollama. Reranker не загружается заново на каждый
вопрос. При переключении базы процесс переоткрывается с её отдельным индексом.
При выходе клиент останавливает процессы, которые запустил сам; существующий
Ollama остаётся работающим. Держите одну копию клиента для одного каталога
конфигурации.

Обновление создаёт отдельную версию индекса; каталог переключается после
успешной сборки. Старые версии и неудачные сборки автоматически не очищаются.
Используются Nomic embeddings, fixed/structured chunking, Qdrant Local и
мультиязычный cross-encoder. Автоматический поиск использует structured,
до 20 кандидатов и до 5 результатов с reranking.

Найденные тексты отправляются выбранному LLM-провайдеру для ответа.
Для managed-базы фрагменты — временный недоверенный контекст текущего запроса:
они не записываются в пользовательское сообщение или постоянную память.
Обычные вопросы и ответы сохраняются по прежним правилам. История может
содержать ответы по ранее выбранным базам; для чистого контекста создайте новый
диалог. В историю попадает итоговый ответ; полный поисковый JSON не сохраняется.

При ошибке поиска клиент не делает LLM-запрос. Пустая выдача даёт локальное
«не знаю»; найденные фрагменты проходят обязательный контракт ответа выше.
Scores не являются вероятностями; качество на пользовательском корпусе ещё
нужно оценить. Reranker ограничивает вопрос 128 своими токенами: если запрос
слишком длинный, сократите его или отключите базу для этого сообщения.

## Внешний локальный сервис и команды разработчика

Предыдущий способ с `Start-DeepSeek-RAG.cmd`, `RAG_URL`, `--rag-status` и
`--rag-search` остаётся дополнительным вариантом для внешнего локального
HTTP-сервиса. Когда выбрана managed-база, его инструмент `rag_search` скрывается,
чтобы не смешивать две базы. `/kb` не импортирует автоматически старый внешний
индекс — создайте базу из его исходных документов.

В `rag-service` доступны команды Python CLI:

```powershell
python -m rag download-models
python -m rag prepare "C:\path\to\documents"
python -m rag index "C:\path\to\documents" --add-source "C:\path\to\other.pdf"
python -m rag search "Вопрос" --no-rerank --strategy fixed
python -m rag evaluate "C:\path\to\questions.json"
python -m rag serve
```

Их нужно выполнять в окружении с `requirements.txt`. Пути задаются через
`RAG_DATA_DIR` и `RAG_MODEL_CACHE`. Для внешнего backend предусмотрен
`QDRANT_URL`; managed-базы всегда используют собственный Local backend.
При ручном управлении Local индексом остановите его владельца перед CLI
индексацией/поиском. HTTP-сервис слушает loopback и предоставляет `/health`
и `/search`; файловые операции и индексация через HTTP не доступны.

## Проверено

Все Go-тесты, vet и сборка прошли. Проверены независимость баз, сохранение
выбора для чатов, добавление/удаление источников, сохранение прежней версии
при сбое, постоянный stdio-процесс, переключение базы и отмена поиска.
TUI-мастер не отправляет ввод названия/пути модели. Полученные фрагменты
маркируются как недоверенные и входят в проверку бюджета контекста.

Все 17 Python-тестов прошли, включая настоящий локальный токенизатор и
reranker из кэша исходного проекта, реальное повторное открытие Qdrant с
тестовыми embeddings, несколько источников и stdio-протокол.
Дополнительно прошёл сквозной прогон через мастер TUI и адаптер клиента с
настоящими Ollama embeddings, Qdrant и reranker из готового окружения:
две базы, переключение, добавление/удаление источника, изменение документа,
переиндексация, восстановление выбора после перезапуска и отключение поиска.
Во всех семи проверках генерации правильные фрагменты поступили тестовой
модели. F2 и ввод в мастере проверены событиями интерфейса.
Полная первоначальная установка из меню и качество
на пользовательских документах ещё не проверены. Последующая проверка с
настоящим DeepSeek и публичным RFC описана ниже.

## День 23: фильтрация и query rewrite

В обычном клиенте выберите базу через F2 / `/kb`, затем задавайте вопросы.
Настройки поиска сохраняются в каталоге баз отдельно для каждого чата:

- `/rag` — показать параметры.
- `/rag baseline` — векторный поиск без фильтров, reranker и rewrite.
- `/rag enhanced` — 20 кандидатов, cosine ≥ 0.49, reranker, его raw logit ≥ -3, до 5 результатов, rewrite.
- `/rag set 30 3` — получить до 30 кандидатов, передать до 3 фрагментов в контекст.
- `/rag threshold 0.6` или `/rag threshold off` — порог cosine.
- `/rag score-threshold -3` или `/rag score-threshold off` — порог сырой оценки reranker.
- `/rag rewrite on|off`, `/rag rerank on|off` — включить/отключить этап; отключение reranker снимает его порог.

Новые чаты используют enhanced, но поиск выполняется только при выбранной базе.
Имеющиеся каталоги читаются без миграции; индекс перестраивать не нужно.
Настройки относятся к управляемым базам, а не к внешнему `RAG_URL`.

Порядок: исходный вопрос → локальный rewrite → embedding → cosine top-K →
cosine-фильтр → cross-encoder reranker → logit-фильтр → финальный top-K → LLM.
Пустой результат остаётся пустым: клиент сообщает об отсутствии подтверждений,
а LLM получает указание не придумывать ответ по документам и ссылки.
В TUI видны число кандидатов, остаток после фильтра, финальные ссылки и изменённый поисковый запрос.

Rewrite удаляет известные вводные и просьбы о кратком формате на русском/английском
по краям вопроса. Он не переводит запрос, не подставляет ожидаемый ответ и не
переписывает историю. Исходный вопрос передаётся LLM без изменения.
Это консервативная локальная эвристика, без дополнительного API-вызова.

Cosine и raw logit — разные шкалы, ни одна не является вероятностью правильного
ответа. Пороги калиброваны на небольшом публичном RFC-корпусе; для другой базы
нужны её контрольные вопросы и повторная настройка. `/rag baseline` позволяет
проверить потери от отсечения. Совпадение ссылки с chunk_id не доказывает, что
фрагмент подтверждает каждое утверждение модели.

Локальный воспроизводимый прогон: `examples/rag-filtering/compare.py` из корня
репозитория с `--model-cache ПУТЬ`. Он использует индекс `artifacts/hw21/index.json`,
отдельные калибровочные вопросы и сохраняет сравнение пяти режимов.
CLI Python `search` и HTTP `/search` поддерживают `min_similarity`,
`min_rerank_score` и `rewrite`; флаги CLI: `--min-similarity`,
`--min-rerank-score`, `--rewrite`.
