# Компонент Agent

Пакет управляет циклом обработки запроса: проверяет ввод, готовит сообщения для
LLM, выполняет выбранный сценарий, проверяет ответы и возвращает результат.
Он не читает файлы, переменные окружения, stdin и не печатает в stdout.
В зависимостях пакета только стандартная библиотека Go.

## Подключение

Пример использования из другого Go-пакета этого приложения:

```go
import (
    "context"
    "os"

    "github.com/eren-erdny/ai_challenge/projects/deepseek-client/agent"
    "github.com/eren-erdny/ai_challenge/projects/deepseek-client/llm"
)

func ask(ctx context.Context, text string) (agent.Result, error) {
    client := llm.New(nil, map[string]string{
        "deepseek": os.Getenv("DEEPSEEK_API_KEY"),
    })
    runner := agent.New(client)
    return runner.Run(ctx, agent.Request{
        ConversationID: "dialog-1",
        Prompt:         text,
        Mode:           agent.Free,
        Target: agent.Target{
            Profile: "deepseek",
            BaseURL: "https://api.deepseek.com/v1",
            Model:   "deepseek-v4-flash",
            SendThinkingDisabled: true,
        },
        Temperature: 0.7,
        Strategy:    agent.Standard,
    })
}
```

`Agent` и HTTP-клиент можно создать один раз и использовать для нескольких
вызовов. В тестах вместо HTTP-клиента передаётся `agent.ClientFunc`.
Ключи принадлежат клиенту; в `Request`, `Result` и метриках полей с ключами нет.

## Контракт

- `Request`: исходный текст, идентификатор диалога, режим, настройки и модели.
- `Result.Responses`: ответы с моделью, метриками, оценкой стоимости и проверками.
- `Result.Analysis`: ответ судьи, если выбран benchmark и анализ завершился.
- `Result.Last()`: последний успешный вызов, включая судью.
- `error`: ошибка ввода, модели, судьи или отмена. Проверяется через `errors.Is`.

При ошибке второй модели первый ответ остаётся в `Responses`. При ошибке судьи
сохраняются все три ответа. Вызывающий код должен обработать и результат, и ошибку.
Провал проверки формата возвращается в `Validation.Passed`, а не как ошибка API.
Автоматических повторов и исправления ответа нет.

## Сценарии и политики

| Режим | Выполнение |
| --- | --- |
| `Free` | Один ответ, без response-control; выбранная стратегия сохраняется |
| `Controlled` | Один ответ с форматом, лимитами и локальной проверкой |
| `Compare` | Ответ без ограничений, затем с ограничениями |
| `TemperatureBenchmark` | Температуры 0, 1.2, 2 с прежними компактными инструкциями, затем судья |
| `ModelBenchmark` | Три цели из `Targets` с одинаковыми настройками; судья использует вторую цель |

В приложении список `Targets` формируется из профилей DeepSeek и Ollama; вторым
участником является DeepSeek Pro. Сам пакет агента не ищет профили в конфигурации.

Input policy проверяет непустой текст, модель, режим, температуру, стратегию и
настройки ограничений до вызова клиента. Она формирует системные инструкции и
сообщение пользователя. Списки целей и stop sequences копируются на запуск.

Output policy выполняет существующие проверки формата, длины и завершения для
ответов с включённым контролем. В benchmark температуры и служебных вызовах
судьи сохраняются прежние инструкции и лимиты без локальной проверки формата.
Судья получает исходную задачу, ответы и метрики. Оценка стоимости использует
существующий справочник тарифов и может отличаться от фактического списания.

## Интерфейс и отмена

TUI и CLI используют `agent_adapter.go`: он переводит настройки приложения в
запрос агента, разрешает ключи провайдеров и передаёт результат функциям вывода.
Агент возвращает данные без оформления терминала.

`context.Context` передаётся от интерфейса до `http.NewRequestWithContext`.
Выход из TUI отменяет активную работу; Ctrl+C отменяет HTTP-вызов в CLI.
После отмены новые шаги сценария не запускаются.

## Будущая память

`ConversationID` уже входит в контракт, но пока только возвращается в результате.
История не сохраняется и не отправляется модели. В дальнейшем хранилище можно
передать агенту отдельной зависимостью. Benchmark должен получать общий снимок
истории для всех участников, не смешивая их ответы.

## Проверка

Из корня репозитория:

```powershell
go test ./projects/deepseek-client/...
```

Тесты покрывают все сценарии, политики, частичные результаты, изоляцию настроек,
отмену и прохождение запроса через локальный HTTP-сервер. Облачные API не нужны.
