# Эксперимент стратегий управления контекстом

Этот сценарий сравнивает `sliding`, `facts` и `branching` без summary. Реальные
ответы и token usage появляются только после запросов к выбранному провайдеру.

## Общие условия

Используйте одну модель, temperature `0`, режим `free`, одинаковый
`context_window`, `max_output_tokens` и `keep_last: 4`. Отключите tools, чтобы
вызовы чтения файлов не меняли расход. Для каждой стратегии создайте новый
Conversation ID и сохраните вывод `/status` в начале и конце.

Из корня репозитория запустите клиент:

```powershell
go run ./projects/deepseek-client
```

В пользовательском `config.json` задайте `history.keep_last` равным `4`, затем
в TUI выполните `/reload`. Для каждого линейного прогона используйте `/new`,
запишите показанный Conversation ID и выберите `/memory sliding` либо
`/memory facts`. Для веточного прогона используйте `/new`, затем
`/memory branching`. Перед сообщениями выполните `/temperature 0`, `/mode free`
и `/tools off`.

## Сценарий на 12 пользовательских сообщений

Отправляйте по одному сообщению и просите отвечать только `Принято`, кроме
последнего шага.

1. Мы собираем ТЗ сервиса бронирования переговорных для компании Orion.
2. Главная цель: сократить двойные бронирования.
3. Пользователи: сотрудники и офис-менеджеры.
4. Ограничение бюджета: 900 000 рублей.
5. Первый релиз должен работать только в веб-браузере.
6. Решение: авторизация через корпоративный SSO.
7. Переговорные имеют вместимость и набор оборудования.
8. Исправление: бюджет составляет 750 000 рублей, прежнее значение отменено.
9. Требование: обычный сотрудник не может удалять чужую бронь.
10. Предпочтение: интерфейс на русском языке.
11. Открытый вопрос: нужна ли интеграция с календарём.
12. Составь итоговое ТЗ: цель, роли, актуальный бюджет, платформа, авторизация,
    сущности, права, язык и открытый вопрос. Не выдумывай отсутствующие решения.

Для `sliding` выполните сценарий линейно. Для `facts` выполните тот же сценарий
линейно и после финала вызовите `/status`: итог включает обычные ответы и
экстракцию facts.

Для `branching` после сообщения 7 выполните:

```text
/checkpoint common
/branch create calendar common
/branch create no_calendar common
```

В ветке `calendar` продолжите сообщениями 8–11 и добавьте решение об интеграции
с календарём. В `no_calendar` повторите сообщения 8–11, но решите отложить
интеграцию. Задайте итоговый вопрос в каждой ветке и убедитесь, что решение одной
ветки не появилось в другой.

Качество оценивайте по девяти явно запрошенным пунктам. Стабильность — по

состояния и необходимость повторять потерянные сведения.
