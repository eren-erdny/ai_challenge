# Защита tool calling

Каждый предложенный моделью вызов проходит проверку до исполнения:

1. Инструмент должен быть зарегистрирован, а параметры — соответствовать его JSON Schema.
2. Аргументы должны быть одним JSON-объектом без повторяющихся ключей. Ограничены размер и глубина вложенности.
3. Для локальных файловых инструментов путь должен быть относительным, без выхода через .. и скрытых сегментов. Проверки реального файлового доступа, расширений и символических ссылок остаются в filetools.
4. В режиме /help разрешён явный список инструментов чтения.
5. При наличии /invariant каждый прошедший предыдущие проверки вызов отдельно проверяется моделью до исполнения.

Отклонённый вызов возвращает структурированную ошибку с executed=false и не передаётся исполнителю. Ошибка, таймаут, некорректный или усечённый ответ обязательного проверяющего останавливают запрос. Проверяющий не получает инструменты. Его токены учитываются, включая известный расход до аварийного завершения.

## Использование

/help без вопроса показывает справку по командам.

/help Как устроен проект? отправляет вопрос ассистенту в режиме только чтения.
Используется выбранная через F2 или /kb база знаний; если база не выбрана,
автоматического поиска по документации нет. Для вопросов о ветке подключите
Git MCP к нужному репозиторию: сервер возвращает состояние своего клона.

Разрешены локальные list_files, read_file, find_files, search_text, rag_search,
Git git_status, git_log, git_diff, git_branches (также с префиксом git__),
github_get_repository (также с префиксом github__). Другие имена в /help
запрещены, даже если модель самостоятельно их запросила. Новый сервер или
инструмент требует пересмотра списка в agent/tool_guard.go; описание и
аннотации MCP не дают ему права на выполнение.

Инварианты задаются существующей командой, например:

/invariant add business Запрещено изменять файлы проекта

При непустом списке инвариантов появляется дополнительный LLM-вызов на каждый
допустимый по схеме и политике tool call, помимо проверки итогового ответа.
Это увеличивает расход и задержку. Пустой список не вызывает проверяющего.

## Границы и проверка

Серверы и их конфигурация должны быть доверенными. Схемы не загружают внешние
ссылки. Проверка LLM может ошибаться; ограничения в Go и файловом исполнителе
применяются независимо от её решения. Выполненные раньше действия не
откатываются при последующем отказе. Защита охватывает модельный tool loop;
ручные CLI-команды администрирования MCP не проходят через него.

Офлайн-тесты проверяют отсутствие исполнения при запрете, параметры, пути,
смешанные пакеты вызовов, имена MCP, отказы и сбои проверяющего, учёт токенов,
маршрутизацию /help в CLI и TUI. Первоначальная проверка защитного слоя была офлайн.
Позднее выполнена [проверка самоподключения проекта](../../examples/developer-assistant/README.md):
реальный RAG, локальный Git MCP и пять ограниченных DeepSeek-вызовов через TUI.
